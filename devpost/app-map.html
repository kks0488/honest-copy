A three-stop reference route

This is a reference route, not a claim of a completed human code tour.

  1. src/main.ts — search el('check').addEventListener. The draft becomes the baseline for comparison. Later changeDraft keeps undo history.
  2. src/rules.mjs — analyze returns exact start/end positions and explanations; applyFinding replaces only the chosen occurrence. applyAll works from the end to preserve offsets.
  3. src/main.ts — renderHighlights uses text nodes and marks, never interprets pasted HTML. renderRevised shows the new draft and score, then copies it.

To change this, start here

A phrase, explanation or local rewrite

Edit rules in src/rules.mjs, then run the exact-span and rewrite tests in tests/rules.test.mjs. These patterns are finite heuristics, not legal judgments.

Layout, labels or risk colors

Labels and page structure live in src/main.ts. Responsive styles and the four category colors live in src/style.css. Preserve category text labels so color is not the only cue.

Optional AI wording and fallbacks

server/rewrite.mjs contains rewrite and createHandler. api/rewrite.mjs adapts it for Vercel. vite.config.ts serves the same handler locally. Secrets stay on the server; tests/rewrite.test.mjs mocks the provider schema.

A practice to reuse

The PRD requires replacing the exact selected phrase. The repeated matches replace only the selected occurrence test in tests/rules.test.mjs checks that the second identical phrase changes while the first stays. Next time, give an agent an observable example before asking it to implement a behavior. A requirement becomes easier to preserve when it has a named document heading and a concrete check.
